## 1️⃣ AI MENTOR LESSON OF THE DAY

### Concept: LLM Agents — Tool Use vs. Agentic Workflow
**Why you need to know this:**  
Because every client (solar, manufacturing, admin) will ask "will this AI just fetch data, or actually *do* work?". Getting the boundary right prevents overpromising.

**Two patterns, one key difference:**

| Pattern | Model controls... | Your control | When to use |
|--------|-------------------|--------------|-------------|
| **Tool Use** | Nothing (you wire the sequence) | Full | Predictable, one-shot tasks |
| **Agentic** | The next-step loop | Guardrails only | Unpredictable, multi-step |

**PENSOLAR example:**  
- **Tool Use:** "When is Sunny Villa's permit approved?" → `get_permit_status()` → answer  
- **Agentic:** "Get Sunny Villa install-ready" → [check permit → chase docs → quote vendors → schedule crew → reschedule on slip]  

**Trade-off (Anthropic):** Agentic loops cost more + latency. Only earn it where rules can't handle variation.

**Your POC takeaway:**  
PENSOLAR's pain is *first* a tool-use + routing problem (slow replies), not autonomy. Start with tool-use demo. Simpler = faster to guardrail.

**Gap you should close next:**  
Write the 3-5 functions your AI will wire up: `get_permit_status`, `get_vendor_quotes`, `notify_customer`. Without that surface, you can't tell which tasks need one call vs. a loop.
