## Concept — the input-integrity gate: a stale or wrong INPUT slips past your recall gate
- **Decide-chain = retrieve → read → reason → decide.** Every gate we taught validates reason/decide: drift + runtime recall (R8), CI recall (2026-08-16 15:00). But if `get_permit_status` / `check_document_gate` returns the WRONG project's permit or a STALE TNB SOP, the agent reasons perfectly and still commits a non-compliant schedule. The defect is upstream of reasoning — the recall gate is blind to it.
- **Stale input = the leakage trap, now at retrieval time.** We taught "snapshot inputs at decision time" when LABELING golden_v1 (2026-08-11). The mirror failure in production: a cached/old read. If the read says "cleared" but TNB revoked on day 3, the agent's decision is "correct" *vs that (wrong) input* → recall reads 100%, yet a real block is missed. Garbage in, compliance out.
- **Catch it at the CHEAPEST stage = before the agent reasons.** A one-line input-integrity assert: `permit_snapshot_age < TTL` (e.g. <24h) AND `returned_project_id == requested_project_id` (no cross-project leak). One cheap read/compare, zero live exposure, zero TNB penalty. This is shift-left taken one layer further than the CI gate — the input gate sits left of even the code gate (runtime → CI → input).
- **PENSOLAR failure it prevents:** dev adds Redis cache to `get_permit_status` (the cost-axis "minimize tool calls" move), TTL = 7 days. TNB revokes a project's approval on day 3; on day 4 the agent reads the cached "cleared" status, reasons perfectly, and commits `commit_schedule` on a now-non-compliant project → 2-wk delay + TNB penalty. The freshness assert fails the read in 0 exposure.
- **Cost lens (his mandate):** caching cuts $/run ONLY if the cached value cannot go stale within TTL in a way that causes a miss. TTL (7d) >> authority revocation latency → caching INVERTS cost (saves tokens, costs a TNB penalty + 2-wk delay). The cost-axis "minimize calls" must be bounded by a freshness SLA; HIGH-consequence reads → short TTL or no cache. Cheapest guardrail = the assertion you ran before reasoning, not the penalty you paid after.
- **It reuses the whole ladder:** a separate *retrieval-precision* eval (evals + golden set — did it read the right doc?); staleness IS data-drift (drift lesson) but now with a mechanism (freshness assert); it is an input-validation fence (guardrails R3). No new artifact strictly required — it's a behavior to add to the 6 read tools in `agent_surface.md` and a line in `rollout_spec.md` §pre-deploy.
