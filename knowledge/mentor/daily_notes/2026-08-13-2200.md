## Concept: Production drift & continuous re-audit — your golden set and recall gate go stale

You built the trust machine: a frozen, audited golden set (R7), a scorer (R5), and a recall-gated autonomy dial (safe rollout). The trap everyone falls into: treat that as *done*. It isn't. The golden set is a **snapshot of the past**, not a guarantee about the future. Here is how it rots — and how to catch it.

- **Three flavors of drift, in PENSOLAR terms.** (1) *Data drift* — the inputs change shape. TNB/authority SOP changes in Q3'26: a status that was "cleared" now needs a second sign-off. Your `golden_v1.csv` frozen at decision-time 2026-03-04 doesn't know. (2) *Concept drift* — the underlying rule moves. Vendor panel churns; a new EPC appears with a failure mode no historical project had. The "should_block" logic no longer covers reality. (3) *Model/provider drift* — the LLM behind `auto_schedule_crew` gets a silent provider update; your prompt now parses permit text differently. Recall slips with **zero code change**.
- **The false comfort**: a one-time 80% eval (R7) and even a perfect frozen-set score lull you. `score_eval.py` vs `golden_v1` can read 100% recall while the tool misses real blocks *live* — because the golden set can't see a world that changed after 2026-03-04. Past correctness ≠ future correctness.
- **Detect on LIVE, not just golden.** Keep the nightly golden-v1 score as your *floor*, but ALSO hold out a rolling sample of **new** real decisions (label them as they close) and score against that. The gap between golden-recall and live-recall is your **drift meter**. And watch the `review_queue` disagreement rate from the safe-rollout lesson — a *rising* disagreement rate is the early warning that fires *before* any block is missed.
- **Set a drift alarm, then auto-rollback.** If live recall < golden recall by more than X%, or review_queue disagreement rate > Y%, that is the SAME breach signal as a recall gate — auto-rollback the dial to 0 and alert. Drift monitoring is the *permanent* version of the safe-rollout gate: that gate protects autonomy TODAY, this one protects your TRUST over time.
- **Re-audit → golden_v2 (this is the loop, not a one-off).** When drift is confirmed, do NOT retune on `golden_v1` (that's training-on-test / leakage). Instead re-label a fresh sample *at decision time* and promote to `golden_v2` — frozen, versioned, never tuned-on. That's the quarterly re-audit Run 7 promised, operationalized.
- **Unify the whole ladder:** R1 stack + R3 guardrails + R5 evals + R7 golden set + safe rollout + drift monitoring = a system trustworthy on day 1 AND day 300. That closes the POC → production → scale arc. Conceptual ladder now spans stack → tool/agentic → guardrails → evals → precision/recall → golden set → safe rollout → **drift & continuous re-audit**.
