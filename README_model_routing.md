# Hermes Model-Selection Automation

Runtime model-selection layer for Hermes Agent. Consumes the daily
`models_sequence.json` (produced by `refresh_models.py`) and keeps the
running agent's per-task auxiliary models pointed at the best *available*
free-tier model, with automatic fallback when a model fails.

## Files

| File | Role |
|------|------|
| `model_router.py` | Library: resolves best available model per aux task, tracks dead-list |
| `apply_model_routing.py` | Writes resolved models into `config.yaml` via `hermes config set` |
| `probe_models.py` | Live 3-token health probe; marks failed models dead (30-min TTL) |
| `models_sequence.json` | Daily catalog (generated by `refresh_models.py` cron) |

## How it works

1. `probe_models.py` pings each free model; failures go to `model_deadlist.json`.
2. `refresh_models.py` refreshes the catalog + per-category free-first chains.
3. `apply_model_routing.py` writes the best healthy model per `auxiliary.<task>`
   into `config.yaml`. The agent reads this on every call — no restart needed.

The daily cron `daily-models-md-refresh` runs: `probe → refresh → apply`.

## Design invariants

- **Fail-safe**: any error keeps the original config-pinned model.
- **Free-tier only**: paid models are never written.
- **Idempotent**: a clean run changes nothing.

## Integration note

For in-process per-call fallback (inside the agent, not via config), patch
`/opt/hermes/agent/auxiliary_client.py`:
- In `_resolve_task_provider_model()`, call `model_router.select_aux_model(task, provider, model)`.
- In the transient-retry failure path, call `model_router.mark_unhealthy(provider, model)`.
(That file lives in a read-only Docker volume; the config-apply path above is
the deployable equivalent.)
